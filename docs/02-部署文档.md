# 学习监控驾驶舱 · 生产部署文档

> 适用：单台公网服务器，Ubuntu 22.04 / Debian 12，前后端分离 + 同域 Nginx 反代。
> 前提：已按 `docs/sql/schema.sql` 完成建表；代码位于 `/workspace/study-cockpit`。

> 多人自助注册及 Docker Compose 部署请优先阅读 [03-多人使用与服务器部署](03-多人使用与服务器部署.md)。本文保留手动 Nginx/systemd 部署流程；其中“建号后关闭注册”适用于仅供指定账号使用的方式。

## 0. 部署目录约定

| 路径 | 用途 | 属主 / 权限 |
|---|---|---|
| `/opt/study-cockpit/backend/target/study-cockpit-1.0.0.jar` | 后端可执行包 | `cockpit:cockpit` `640` |

## 2. MySQL 初始化

```bash
# 2.1 时区配置 /etc/mysql/mysql.conf.d/mysqld.cnf
# [mysqld]
# default-time-zone = '+08:00'
# character-set-server = utf8mb4
# collation-server = utf8mb4_0900_ai_ci
# bind-address = 127.0.0.1          # 仅本机，不对公网暴露
sudo systemctl restart mysql

# 2.2 建表（完整语句见 docs/sql/schema.sql）
sudo mysql -u root -p < /workspace/study-cockpit/docs/sql/schema.sql
# 或使用随项目提供的脚本（会自动定位 schema.sql）：
# sudo /workspace/study-cockpit/deploy/scripts/init-db.sh

# 2.3 最小权限账号（只授权业务库，禁止 root 远程登录）
sudo mysql -u root -p <<'SQL'
CREATE USER 'cockpit'@'127.0.0.1' IDENTIFIED BY '换成强密码';
GRANT SELECT, INSERT, UPDATE, DELETE ON study_cockpit.* TO 'cockpit'@'127.0.0.1';
FLUSH PRIVILEGES;
SQL
```

> 说明：业务数据为逻辑删除、图片记录为物理删除，账号不需要 `DROP/ALTER` 权限。

## 3. 密钥与环境变量（安全要求 7）

```bash
sudo install -d -m 750 -o cockpit -g cockpit /etc/study-cockpit
sudo cp /workspace/study-cockpit/deploy/env.example /etc/study-cockpit/env
sudo chmod 600 /etc/study-cockpit/env
sudo chown cockpit:cockpit /etc/study-cockpit/env

# 分别生成两个不同的 >=32 字节随机密钥
openssl rand -base64 48     # -> 填入 JWT_SECRET
openssl rand -base64 48     # -> 填入 FILE_TOKEN_SECRET（勿与上面相同）

sudo vi /etc/study-cockpit/env   # 填 DB_PASSWORD / 两个密钥 / DB_URL 等
```

必填项：`DB_PASSWORD`、`JWT_SECRET`、`FILE_TOKEN_SECRET`。
`AppProperties#validate()` 会在启动时 fail-fast：缺失、长度不足 32 字节、两密钥相同、`FILE_STORAGE_DIR` 非绝对路径或位于 Web 静态目录、JWT 有效期超出 1~120 分钟，任一不满足直接启动失败。

## 4. 图片目录权限（安全要求 5）

```bash
sudo install -d -m 750 -o cockpit -g cockpit /data/study-cockpit/uploads
sudo install -d -m 750 -o cockpit -g cockpit /var/log/study-cockpit

# 目录不授予执行权限给 other，文件不授予任何执行位
sudo find /data/study-cockpit -type d -exec chmod 750 {} \;
sudo find /data/study-cockpit -type f -exec chmod 640 {} \;

# 可选：以 noexec 挂载独立分区，彻底禁止执行上传文件
# /etc/fstab:  /dev/xxx  /data/study-cockpit  ext4  defaults,noexec,nosuid,nodev  0 2
```

Nginx 配置中 `location ^~ /uploads { deny all; }`，且该目录本就不在 `root` 下，任何图片必须经 `/api/images/{id}/raw` 鉴权接口返回。

## 6. systemd 服务

```bash
sudo cp /workspace/study-cockpit/deploy/systemd/study-cockpit.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now study-cockpit
sudo systemctl status study-cockpit
journalctl -u study-cockpit -f          # 查看启动日志与配置校验结果
```

服务以 `User=cockpit` 运行，`EnvironmentFile` 注入密钥，`-Duser.timezone=Asia/Shanghai` 固定 JVM 时区，`server.shutdown=graceful` 保证优雅关闭。

## 7. Nginx + HTTPS

```bash
sudo cp /workspace/study-cockpit/deploy/nginx/study-cockpit.conf \
        /etc/nginx/sites-available/study-cockpit
sudo ln -s /etc/nginx/sites-available/study-cockpit /etc/nginx/sites-enabled/
sudo nginx -t

# 证书（先保证 80 端口可达；配置里已做 301 跳转，certbot 用 webroot 或 standalone 均可）
sudo certbot --nginx -d your-domain.example

sudo systemctl reload nginx
```

配置要点：

| 项 | 作用 |
|---|---|
| `server_tokens off` | 不泄露 Nginx 版本 |
| `add_header Strict-Transport-Security` | HSTS，强制 HTTPS；Cookie 的 `Secure` 依赖它 |
| `client_max_body_size 5m` | 上传大小第一道闸门（后端 `FILE_MAX_SIZE` 为第二道） |
| `location ^~ /uploads { deny all; }` | 图片目录禁止 Web 直访 |
| `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for` | 后端限流取 XFF **最后一个**值，客户端伪造的前缀无法绕过限流 |
| `add_header Cache-Control "no-store"` | API 响应由后端统一设置，前端页面与 index.html 不缓存 |

> 安全响应头（CSP / nosniff / DENY / Referrer-Policy / Permissions-Policy）由后端 `RequestContextFilter` 统一设置，Nginx 不重复覆盖。

## 8. 初始化登录账号

个人部署推荐「临时开放注册 → 建号 → 立即关闭」：

```bash
# 临时把 /etc/study-cockpit/env 中 APP_ALLOW_REGISTER 改为 true
sudo systemctl restart study-cockpit

# CSRF 双提交：先取 XSRF-TOKEN，再带着 Cookie + Header 注册
curl -c /tmp/cj.txt https://your-domain.example/api/auth/csrf
TOKEN=$(awk '$6=="XSRF-TOKEN"{print $7}' /tmp/cj.txt)
curl -b /tmp/cj.txt -H "X-XSRF-TOKEN: $TOKEN" \
     -H "Content-Type: application/json" \
     -d '{"username":"yourname","password":"强密码至少8位","nickname":"我"}' \
     https://your-domain.example/api/auth/register

# 立刻改回 false 并重启（此后注册接口返回 403）
sudo sed -i 's/APP_ALLOW_REGISTER=true/APP_ALLOW_REGISTER=false/' /etc/study-cockpit/env
sudo systemctl restart study-cockpit
```

备选：执行 `deploy/scripts/init-user.sh <用户名>`，脚本交互式读取密码、用 BCrypt(12) 生成密文并**输出**待执行的 `INSERT` SQL（不直接写库，便于核对）。密文前缀 `$2y$` 可被 Spring Security 识别。**任何情况下都不要明文写入密码。**

## 9. 部署后验证清单

```bash
# 9.1 未登录访问业务接口 -> 401
curl -i https://your-domain.example/api/dashboard/overview

# 9.2 登录 -> Set-Cookie 应含 HttpOnly; Secure; SameSite=Strict
curl -i -c /tmp/cj.txt -H "Content-Type: application/json" \
     -d '{"username":"yourname","password":"强密码至少8位"}' \
     https://your-domain.example/api/auth/login

# 9.3 安全响应头
curl -I https://your-domain.example/api/auth/me | grep -Ei 'content-security|x-frame|x-content|referrer|cache'

# 9.4 越权/不存在资源 -> 404（不泄露资源是否存在）
curl -b /tmp/cj.txt -i https://your-domain.example/api/goals/999999

# 9.5 上传伪装脚本（应被 415 拒绝）
echo '<script>alert(1)</script>' > /tmp/evil.jpg
curl -b /tmp/cj.txt -H "X-XSRF-TOKEN: $TOKEN" \
     -F "file=@/tmp/evil.jpg;type=image/jpeg" \
     https://your-domain.example/api/tasks/1/images

# 9.6 CSV 导出（应带 BOM、attachment、仅图片标记）
curl -b /tmp/cj.txt -o /tmp/weekly.csv \
     'https://your-domain.example/api/reports/weekly/export?weekStart=2026-11-23'
file /tmp/weekly.csv && head -2 /tmp/weekly.csv
```

**运行时检查**：
- `journalctl -u study-cockpit | grep 配置校验通过`
- 确认 `management` 端点全部关闭：`curl https://your-domain.example/actuator` 应为前端 404 页面，不返回任何环境信息
- 生产报错响应体只有 `{code,message,traceId,timestamp}`，不含堆栈

**定时任务**（Cron 均为 UTC+8）：

| 时间 | 任务 |
|---|---|
| 每日 03:00 | 图片 15 天到期清理（文件 + 记录） |
| 每小时 | 积压任务扫描，触发 `NotificationSender` |
| 每周日 23:59 | 周结算生成 `weekly_summary` 快照（幂等） |

## 10. 备份、升级与回滚

```bash
# 备份（图片 15 天自动过期，无需长期归档；数据库需定期备份）
sudo mysqldump --single-transaction -u cockpit -p study_cockpit \
  | gzip > /backup/study_cockpit_$(date +%F).sql.gz
```

### 10.1 修改密码

登录后在页面右上角「修改密码」更新口令，对应接口 `POST /api/auth/change-password`。
后端校验旧密码后以 BCrypt(12) 存储新密文，并在同一条 SQL 中将 `token_version + 1`，使该用户所有旧 JWT 失效，前端跳转回登录页。更新条件校验原会话版本；并发改密只有一个请求能成功，避免覆盖新密码。

### 10.2 定时备份脚本

仓库提供 `deploy/scripts/backup-db.sh`，默认备份到 `/backup/study-cockpit`，保留 14 天。先写入私有临时文件，完成压缩校验后再发布备份；只有成功备份后才清理过期文件，失败时保留既有备份。
建议为备份创建一个只读账号（仅 `SELECT` 权限），不要用业务写账号跑备份。

```bash
# 授予只读备份账号（示例）
sudo mysql -u root -p <<'SQL'
CREATE USER 'cockpit_backup'@'127.0.0.1' IDENTIFIED BY '强备份密码';
GRANT SELECT ON study_cockpit.* TO 'cockpit_backup'@'127.0.0.1';
FLUSH PRIVILEGES;
SQL

# 安装脚本和备份目录，保证 cockpit 用户可写
sudo install -d -m 750 -o cockpit -g cockpit /opt/study-cockpit/deploy/scripts /backup/study-cockpit
sudo install -m 750 -o cockpit -g cockpit \
  /workspace/study-cockpit/deploy/scripts/backup-db.sh \
  /opt/study-cockpit/deploy/scripts/backup-db.sh

# 创建配置文件，填写 DB_PASSWORD='自己的备份密码'（按 shell 语法引用）
sudo touch /etc/study-cockpit/backup-env
sudo chown cockpit:cockpit /etc/study-cockpit/backup-env
sudo chmod 600 /etc/study-cockpit/backup-env
sudoedit /etc/study-cockpit/backup-env

# 先手动验证，再配置每天 02:30 执行
sudo -u cockpit sh -c 'set -a; . /etc/study-cockpit/backup-env; exec /opt/study-cockpit/deploy/scripts/backup-db.sh'
sudo crontab -u cockpit -e
# 30 2 * * * set -a; . /etc/study-cockpit/backup-env; /opt/study-cockpit/deploy/scripts/backup-db.sh >> /var/log/study-cockpit/backup.log 2>&1
```

`backup-env` 至少包含 `DB_PASSWORD`（备份账号密码），可选覆盖 `DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USER`、`BACKUP_DIR`、`BACKUP_KEEP`。数据库名只接受字母、数字和下划线，保留天数必须是非负整数。

此脚本适用于当前项目的 InnoDB 表结构，不备份数据库用户/授权、存储过程或事件。图片文件不在数据库备份内。上线前应定期将备份恢复到独立测试库，验证可用性；以下示例会写入指定库，必须使用空的测试库：

```bash
# 将占位文件名替换为实际备份文件；不要指向正在使用的业务库
gzip -t /backup/study-cockpit/实际备份文件.sql.gz
mysql -u root -p -e 'CREATE DATABASE study_cockpit_restore CHARACTER SET utf8mb4;'
gzip -dc /backup/study-cockpit/实际备份文件.sql.gz | mysql -u root -p study_cockpit_restore
```

```bash
# 升级：先停服务 -> 替换 jar/dist -> 启动 -> 跑验证清单
sudo systemctl stop study-cockpit
# ...替换文件...
sudo systemctl start study-cockpit

# 回滚：保留上一版 jar，改回软链/文件后重启
```

## 11. 安全机制对照自检（上线前逐条打勾）

| # | 要求 | 落地位置 | 部署侧检查 |
|---|---|---|---|
| 1 | BCrypt 加盐 | `SecurityConfig#passwordEncoder(12)` | DB 中 `password` 以 `$2a$12$` / `$2y$12$` 开头 |
| 2 | JWT 短有效期 / 防篡改 / 防重放 | `JwtTokenProvider` + `SecurityCacheService` | Cookie 带 HttpOnly/Secure/SameSite=Strict；改 `JWT_TTL_MINUTES` 生效 |
| 3 | 全局限流 / 登录防爆破 | `RateLimitFilter` + `LoginAttemptService` | 连续 5 次错误密码后返回 429 |
| 4 | 入参校验 / SQL 注入 / XSS | Validation + `#{}` 绑定 + `XssFilter` + CSP | 上传/表单提交 `<script>` 返回 400 |
| 5 | 上传双重校验 / 目录隔离 | `FileGuard` + `LocalFileStorageServiceImpl` | 目录 750、文件 640、Nginx deny |
| 6 | 关闭调试端点 / 不返回堆栈 | `application-prod.yml` + `GlobalExceptionHandler` | `/actuator` 不可用；报错体无堆栈 |
| 7 | 密钥环境变量 | `AppProperties#validate` | `/etc/study-cockpit/env` 权限 600，仓库无密钥 |
| 8 | 统一权限拦截 / 数据隔离 | `SecurityConfig` + `SecurityUtils` | 9.1 / 9.4 验证通过 |
| 9 | 安全响应头 / 索引 | `RequestContextFilter` + `schema.sql` | 9.3 验证通过；`SHOW INDEX` 可见 16 个索引 |
| 10 | 图片访问鉴权 | `ImageUrlSigner` + `TaskImageController` | 换账号访问他人图片 URL 返回 404 |

## 12. 已知限制

- 单机部署：限流与登录锁定基于进程内 Caffeine，重启后计数清零；多实例需替换为集中式存储。
- 图片临时地址默认 30 分钟有效，前端刷新列表会重新签发；CSV 中的 `[IMAGE]` 仅为标记，不含链接。
- 邮件提醒仅预留 `NotificationSender` 接口，本期未实现发送通道（需求范围内）。
- 对象存储仅预留 `StorageService` 扩展位，本期为本地目录实现。
- `weekly_summary` 由周日结算任务生成，首次部署后历史周无基线数据，运行满 1 周后基线可用；可用手动触发结算任务补算。
